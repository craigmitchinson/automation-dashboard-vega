# automation-dashboard-vega

- What: the automation-dashboard React app rebuilt as Kibana 8 dashboards of Vega panels. This `source` branch builds; `main` holds only the deliverable, assembled by `scripts/publish.sh` (never hand-edit main). Read README.md, then publish/docs/LOGSTASH.md and JOBS.md before touching the ETL.
- Specs are generated: edit `vega/panels/*.mjs` or `vega/lib/*`, never `dist/`. Colours/fonts only in `vega/lib/tokens.mjs` (Platform Health palette; spoke colours come from reference.json); number formats only in `vega/lib/fmt.mjs`.
- User docs live in publish/ (README and docs/KIBANA, LOGSTASH, JOBS, FORMULAS) and describe main's layout (kibana/, logstash/, previews/). Building in Kibana is UI only: paste devtools-setup.txt into Dev Tools, import the ndjson. `KIBANA_VERSION=x.y.z npm run build` stamps saved objects for an older Kibana; `NO_CONTROLS=1` leaves controls out.
- Commands: `npm run mock` (once), `npm run build`, `npm test`, `npm run test:etl`, `npm run preview` (writes dist/previews and dist/mock for main).
- Production runs only on Kibana and Logstash: no Python, cron or other hosts. Service checks (vega/lib/service.mjs) are evaluated in Vega on the Service dashboard; five of the nine (`alert: true`) also exist as Kibana `.es-query` rules generated by vega/alert-rules.mjs into the import ndjson (`NO_RULES=1` leaves them out). The other four compare against a 4-week usual, which a rule cannot do. Change thresholds in `SERVICE`, rebuild, and keep the rule table in publish/docs/JOBS.md in step. tests/service.test.mjs holds the expected statuses at seeded moments.
- The ETL rules exist twice: JS reference in etl/reference-impl, Ruby in etl/logstash (ia-enrich.rb for items, ia-cost.rb with ia-cost-daily.conf and ia-cost-stamp.conf for cost). Change both and run `npm run test:etl`.
- Vega expression gotchas found so far: no `sum()`, `concat()` or function literals (use aggregate datasets and `indexof(pluck())`); named marks create datasets so names must be unique; `%context%` cannot sit alongside `body.query`; groups need `encode.update.clip` to hide children.
- UI copy: UK English, no em dashes.
